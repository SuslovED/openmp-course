Код лежит в каталоге [`code/`](code/) рядом с этим файлом, все команды ниже выполняются из него:

```bash
cd seminars/s01-vvedenie/code

make             # собрать все примеры
```

Число потоков задаётся переменной окружения `OMP_NUM_THREADS`:

| Где работаете | Запуск на 4 потоках |
|---|---|
| Linux, WSL, macOS, MSYS2 | `OMP_NUM_THREADS=4 ./hello` |
| PowerShell | `$env:OMP_NUM_THREADS=4; .\hello.exe` |

Не собирается — посмотрите вывод `make info` и раздел «Частые проблемы» в [`docs/02-okruzhenie.md`](../../docs/02-okruzhenie.md), потом пишите в чат курса: полный текст ошибки и вывод `make info`. Без `make` можно собрать вручную: `gcc -O2 -fopenmp hello.c -o hello` (на macOS вместо `gcc` — `gcc-15` или та версия, которую поставил Homebrew).

## 1. Блочное разбиение π

Файл [`code/practice/pi_practice.c`](code/practice/pi_practice.c). Сейчас он считает π последовательно.

1. Распараллельте его в стиле SPMD, как в MPI: поток `id` из `nt` берёт **непрерывный** диапазон индексов `[begin, end)` (на семинаре было циклическое разбиение `i += nt`).
2. Остаток от деления `n` на `nt` не должен потеряться: каждая из `n` итераций выполняется ровно один раз.
3. Сумму каждый поток копит в локальной переменной и добавляет к общей `sum` **один раз** (`critical` или `atomic`).

Сборка и проверка:

```bash
make practice/pi_practice
OMP_NUM_THREADS=1 ./practice/pi_practice 100000007
OMP_NUM_THREADS=3 ./practice/pi_practice 100000007   # ошибка должна остаться порядка 1e-13
OMP_NUM_THREADS=4 ./practice/pi_practice
```

Если на 3 потоках ошибка заметно больше, чем на одном, ищите итерации, которые потерялись или посчитаны дважды.

## 2. Сначала прогноз, потом замер

**Прогноз.** Не запуская программу, запишите, какое ускорение S(p) = T(1) / T(p) вы ожидаете:

| p | 2 | 4 | 8 | = физ. ядер | = лог. процессоров | 2 × лог. |
|---|---|---|---|---|---|---|
| прогноз S(p) | | | | | | |

**Замер.** На каждое p не меньше 5 повторов, берём медиану. Удобнее всего скриптом курса (нужен Python 3):

```bash
python3 ../../../tools/bench.py --cmd "./practice/pi_practice {n}" \
    --threads 1,2,4,8 --set n=400000000 --repeat 5 --out t_pi.csv
python3 ../../../tools/plot.py t_pi.csv --kind speedup --table
```

Список потоков подберите под свою машину: 1, 2, 4, число физических ядер, число логических процессоров, вдвое больше логических. Ноутбук на зарядке, браузер и видеосвязь закрыты.

Сравните с прогнозом: где ускорение перестало расти и почему? В ДЗ0 вы сделаете такой же замер аккуратно и опишете его в отчёте.
