# OpenMP — репозиторий студента

Фамилия Имя: …    Вариант (номер в журнале): …

Это личный репозиторий для всех домашних заданий курса «Параллельное программирование на OpenMP».
Он создан из шаблона: внутри уже есть сборка под Linux/WSL/macOS/MSYS2, скрипты замеров и CI,
который проверяет каждую сдачу.

## Структура

```
common.mk            определение компилятора и флагов OpenMP — не трогайте без необходимости
SYSTEM.md            паспорт вашего стенда (ДЗ0)
tools/               bench.py (замеры), plot.py (графики), sysinfo.* (паспорт), check_report.py (CI)
hw0/ hw1/ hw2/ hw3/  домашние задания
project/             мини-проект (ДЗ4)
  Makefile           цели: all, test, tsan, bench, plots, clean
  src/               исходники
  results/           сырые данные замеров *.csv — КОММИТЯТСЯ
  plots/             графики *.png — КОММИТЯТСЯ
  REPORT.md          отчёт
  SOURCES.md         источники и инструменты
.github/workflows/ci.yml   автоматическая проверка
```

## Начало работы

1. Нажмите **Use this template** (GitHub) или сделайте fork/импорт (GitLab), репозиторий — **приватный**,
   добавьте преподавателя в соавторы.
2. Склонируйте и установите окружение по инструкции курса (`docs/02-okruzhenie.md`).
3. Проверьте, что всё работает:
   ```bash
   cd hw0
   make info        # какой компилятор и флаги выбраны
   make             # сборка
   make test        # корректность на 1, 2, 4 потоках
   make tsan        # поиск гонок (Linux/WSL; на macOS — если установлен brew llvm)
   ```
4. Сгенерируйте паспорт стенда в корне репозитория:
   `bash tools/sysinfo.sh` (Linux/WSL/macOS) или
   `powershell -ExecutionPolicy Bypass -File tools\sysinfo.ps1` (Windows).

## Сборка на разных системах

| Система | Что делать |
|---|---|
| Linux, WSL2 (Ubuntu) | `make` — используется `gcc -fopenmp` |
| macOS + `brew install gcc` | `make` — автоматически выберется `gcc-14`/`gcc-15` |
| macOS только с Apple clang | `brew install libomp`, затем `make` (флаги `-Xpreprocessor -fopenmp -lomp` подставятся сами) |
| Windows, MSYS2 UCRT64 | в терминале UCRT64: `make` (программы с `.exe`; TSan недоступен — смотрите CI или используйте WSL) |
| Другой компилятор | `make CC=clang` / `make CC=gcc-14` |

Число потоков задаётся переменной окружения: `OMP_NUM_THREADS=4 ./build/pi 100000000`.

## Как сдавать ДЗ

1. **Прогноз до замеров.** Заполните раздел «Прогноз» в `hwN/REPORT.md` и сделайте отдельный коммит.
   CI проверяет по истории git, что прогноз появился раньше результатов.
2. **Код.** `make test` и `make tsan` проходят.
3. **Замеры на своей машине.** Ноутбук на зарядке, лишние программы закрыты. `make bench` пишет
   `results/*.csv`, `make plots` строит графики. Число потоков можно поменять: `make bench THREADS=1,2,4,6,8`.
4. **Отчёт и источники.** Допишите `REPORT.md` и `SOURCES.md`, удалите из них строку `template:unfilled`.
5. **Push.** CI должен быть зелёным (вкладка Actions). Проверить комплектность локально:
   `python3 tools/check_report.py hwN`.

Правила про источники: пользоваться можно чем угодно — книгами, спецификацией, сайтами, примерами
из интернета, инструментами редактора, помощью однокурсников. Но на защите вы объясняете и меняете
любую строку без посторонней помощи, все числа в отчёте — с вашей машины, а в `SOURCES.md` указано,
чем вы пользовались и как проверяли взятое.
