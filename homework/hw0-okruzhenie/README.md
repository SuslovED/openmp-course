# ДЗ0. Окружение и паспорт стенда

**Выдаётся:** на С1. **Срок:** до начала С2. **Объём:** около часа, если окружение встаёт без проблем.
**Зачем:** все домашние задания выполняются на вашем компьютере, а отчёты опираются на замеры с него. Это ДЗ нужно, чтобы к С2 у всех собирался OpenMP-код, работали скрипты замеров и CI, и чтобы вы знали, на какой машине мерите.

## Что сделать

### 1. Репозиторий

1. Создайте **приватный** репозиторий из шаблона курса (ссылку даст преподаватель; в материалах курса — `templates/student-repo/`): кнопка *Use this template* на GitHub или импорт на GitLab.
2. Добавьте преподавателя в соавторы.
3. В корневом `README.md` впишите фамилию, имя и номер варианта `V` — это ваш номер в журнале (1–17). По нему выбираются параметры во всех следующих ДЗ.

### 2. Окружение

Установите компилятор с поддержкой OpenMP по инструкции [docs/02-okruzhenie.md](../../docs/02-okruzhenie.md):

| Система | Рекомендуемый путь |
|---|---|
| Linux | `gcc` из пакетов дистрибутива; для TSan — `clang` + `libomp-dev` |
| Windows | **WSL2 + Ubuntu** (лучше всего); запасной вариант — MSYS2 UCRT64 |
| macOS | `brew install gcc` (настоящий gcc) или Apple clang + `brew install libomp` |

Visual Studio (`/openmp`) не подходит: это OpenMP 2.0.

Проверка:

```bash
cd hw0
make info      # какой компилятор и флаги выбраны
make           # собирает build/hello и build/pi
make test      # pi на 1, 2, 4 потоках совпадает с эталоном
make tsan      # ThreadSanitizer (Linux/WSL; на macOS при наличии brew llvm; в MSYS2 — только в CI)
OMP_NUM_THREADS=4 ./build/hello
```

`hello` должен напечатать четыре приветствия в произвольном порядке и версию OpenMP (`_OPENMP`). Запишите, какое значение `_OPENMP` выдаёт ваш компилятор.

### 3. Паспорт стенда `SYSTEM.md`

В **корне** репозитория выполните:

- Linux, WSL, macOS: `bash tools/sysinfo.sh`
- Windows (PowerShell): `powershell -ExecutionPolicy Bypass -File tools\sysinfo.ps1`

Скрипт заполнит `SYSTEM.md`. Проверьте его глазами и допишите то, что скрипт не определил. В паспорте должно быть:

- модель процессора;
- число **физических** ядер и **логических** процессоров;
- есть ли деление на производительные и энергоэффективные ядра (Intel 12-го поколения и новее — P/E; Apple M1–M4 — performance/efficiency), сколько каких;
- объёмы кэшей L1d, L2, L3;
- объём ОЗУ;
- ОС (и WSL, если используете);
- компилятор, его версия и значение `_OPENMP`;
- режим питания при замерах (от сети / от батареи, «сбалансированный» / «производительность»).

На Windows с WSL запустите **оба** скрипта: `sysinfo.ps1` в Windows видит P/E-ядра и кэши лучше, чем WSL. Объедините сведения в один `SYSTEM.md`.

### 4. Прогноз — до замеров

Откройте `hw0/REPORT.md`, заполните раздел **«Прогноз»** и **закоммитьте его отдельным коммитом** до запуска замеров:

```bash
git add hw0/REPORT.md && git commit -m "ДЗ0: прогноз" && git push
```

Ответьте числами:
1. Какое ускорение `pi` вы ожидаете на 2, 4, на числе физических ядер, на числе логических процессоров?
2. Что произойдёт, если запустить вдвое больше потоков, чем логических процессоров?
3. Есть ли у вас E-ядра, и как, по-вашему, это скажется на графике?

Неверный прогноз не штрафуется. Штрафуется только отсутствие объяснения, почему реальность разошлась с прогнозом.

### 5. Первый замер

Ноутбук на зарядке, режим «производительность», браузер и IDE закрыты.

```bash
cd hw0
make bench THREADS=1,2,4,8,16       # список до 2 × числа логических процессоров
make plots
```

`make bench` запускает `tools/bench.py`: каждую конфигурацию 5 раз после прогрева, результат в `results/pi.csv`. `make plots` строит `plots/pi_time.png`, `plots/pi_speedup.png`, `plots/pi_eff.png`. Числа потоков подберите под свою машину: обязательно 1, 2, число физических ядер, число логических процессоров и 2 × логических.

Коммитятся и `results/*.csv`, и `plots/*.png`.

### 6. Короткий отчёт `hw0/REPORT.md`

Разделы шаблона (Прогноз, Стенд, Методика, Результаты, Объяснение, Выводы) — по 2–5 предложений:

- **Стенд:** ссылка на `../SYSTEM.md` и главное для этого замера (ядра, P/E, питание).
- **Методика:** точная команда, число повторов, что считается итоговым временем (медиана).
- **Результаты:** график ускорения и таблица (`python3 ../tools/plot.py results/pi.csv --kind speedup --table`).
- **Объяснение:** сравните с прогнозом. Где ускорение перестало расти и почему? Что происходит при числе потоков больше логических процессоров?
- **Выводы:** сколько потоков вы будете использовать для замеров в следующих ДЗ и почему.

### 7. Источники и инструменты `hw0/SOURCES.md`

Укажите, чем пользовались: инструкции, сайты, подсказки однокурсников, инструменты в редакторе — даже если это помогло только с установкой. Если ничего, кроме материалов курса, не понадобилось, так и напишите.

### 8. CI

Сделайте `git push` и проверьте вкладку **Actions** (GitHub) или **CI/CD** (GitLab): все задачи должны быть зелёными. Перед сдачей удалите из `REPORT.md` и `SOURCES.md` строку `template:unfilled`: без этого CI не проверяет комплектность отчёта.

## Если не получается

1. Раздел «Частые проблемы» в [docs/02-okruzhenie.md](../../docs/02-okruzhenie.md).
2. Чат курса: присылайте **полный** текст ошибки и вывод `make info`.
3. Если окружение так и не заработало, напишите преподавателю заранее, до С2: договоримся о коротком созвоне с демонстрацией экрана. На С2 выдаётся ДЗ1, и без рабочего компилятора его не сделать.

## Вопросы для самопроверки (их могут задать по отчёту или на зачёте)

- Сколько у вас физических ядер и логических процессоров? Как это видно на вашем графике ускорения?
- Почему ускорение на числе логических процессоров меньше их числа?
- Что происходит при переподписке (потоков больше, чем процессоров), и почему время растёт не сильно?
- Почему для замера используется медиана, а не среднее и не минимум?
- Почему `pi` на 1 и 4 потоках может отличаться в последних знаках?
