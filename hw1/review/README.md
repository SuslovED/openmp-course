# Аудит чужой версии Ньютона

В чужой версии `collapse(2)` распределяет отдельные точки сетки. Каждый поток пишет в свой набор элементов `root` и `iters`, а общая сумма собрана редукцией. Команды `make build/newton build/newton_ext` собрали обе версии с одинаковыми флагами. При `OMP_NUM_THREADS=16` на сетке 300×300 режим `check` дал `RESULT 0` при всех расписаниях из таблицы.

На MacBook Air с Apple M2 измерил обе версии на варианте 13, сетке 2000×2000 и 16 потоках. В каждом из пяти повторов конфигурации запускались в порядке таблицы. В каждом запуске сумма итераций равнялась 54 903 651. Исходные замеры в [benchmark.csv](benchmark.csv).

| Версия | OMP_SCHEDULE | Медиана, с |
|---|---|---:|
| rows | `static` | 0.206281 |
| collapse | `static` | 0.233122 |
| rows | `dynamic,1` | 0.178445 |
| collapse | `dynamic,2000` | 0.173940 |
| collapse | `dynamic,1` | 0.299300 |

При `collapse(2)` порция `dynamic,1` содержит одну точку, а при построчном цикле — целую строку. Для сопоставимой порции по 2000 точек использовал `dynamic,2000` у чужой версии. Мелкая порция в одну точку увеличивает число обращений к планировщику с примерно 2000 до 4 млн. Замер показывает, почему размер порции нужно пересчитать при переходе на `collapse(2)`.

`make build/newton_ext_tsan` собрал инструментированную копию. Запуск `OMP_NUM_THREADS=2 OMP_SCHEDULE=static ./build/newton_ext_tsan 13 120 120 check` завершился с кодом -6 по данным Python. Вывод в [tsan.log](tsan.log). Локальный прогон проверку не прошёл: TSan сообщил о доступах к сумме по разные стороны выхода из OpenMP-региона. Аналогичное предупреждение было у основной версии. Archer на стенде недоступен, так что этот вывод не позволяет подтвердить природу предупреждения.
